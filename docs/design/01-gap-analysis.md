## 一、v1.0 方案优点盘点

v1.0 作为架构级方案，已具备良好的工程起点：

1. **三层混合架构清晰** — 规则引擎 → 知识库 → LLM 分级处理，兼顾准确率与成本，方向正确。
2. **意图驱动路由** — 6 类意图 + 置信度阈值路由，避免所有问题都走 LLM 的成本陷阱。
3. **领域适配思路明确** — 借鉴食品领域智能体（`Taro版/`）的可复用模式，列出"保留架构/重新设计"矩阵。
4. **记忆与个性化** — 区分偏好、案件档案、对话历史、使用习惯四类记忆，定位精准。
5. **渐进式交付** — 五阶段路线图，每阶段有交付物与验收标准，节奏合理。
6. **YAGNI 裁剪** — 明确不做在线律师、视频、多语言、跨平台、付费，聚焦 MVP。
7. **风险识别到位** — 列出 6 类风险与缓解措施，风险意识良好。

### 2.1 v2.3 AI 律师增强方向差距分析（v2.3）

v2.0/v2.1/v2.2 已闭合上述 G1–G30 的 P0/P1 缺口。v2.3 围绕"将系统升级为功能增强的 AI 律师系统"的 7 大完善方向，识别 v2.2 仍存在的差距并给出解决方案映射，作为 v2.3 设计的缺口依据（落点验收见 00 第八节）。

| # | v2.3 方向 | v2.2 仍存在的差距 | v2.3 解决方案 | 落点文档 |
|---|----------|------------------|--------------|---------|
| V1 | NLU 自然语言理解 | 意图识别仅关键词+置信度匹配，无法处理复合意图、实体缺失、需澄清场景 | EntityExtractor 四层架构（正则→词典→LLM NER→上下文消解）+ ClarificationManager 状态机（≤3 轮）+ CompoundIntentSplitter 依赖图拓扑 | 07 第八节 / 11 nlu Agent |
| V2 | 知识库扩充与时效 | 法条静态导入，无失效检测、无引用关系图，可能引用已废止法条 | LawTimelinessScanner 三步算法（状态检测→交叉引用→预警）+ CitationGraphBuilder 增量 upsert + law_citation_graph 集合 | 15 第十三节 / 14 第十四节 |
| V3 | 逻辑推理能力 | 仅 RAG 检索 + LLM 生成，无法条适用判定与案情相似度计算，结论不可溯源 | IRAC 推理框架（Issue/Rule/Application/Conclusion）+ FactSimilarityService + LawApplicationDeterminer + CaseComparator + reasoning_chain 持久化 | 16 / 07 第九节 / 11 reasoning Agent |

## 三、可行性评估

### 3.1 技术可行性

| 项 | 评估 | 说明 |
|----|------|------|
| Taro + 微信云开发 | ✅ 成熟 | 与 `Taro版/` 同栈，团队有经验 |
| 三层混合架构 | ✅ 可行 | 规则引擎与知识库本地/云数据库，LLM 走云函数代理 |
| 混合检索（BM25+向量） | ⚠️ 需选型 | 云数据库无原生向量索引，需引入向量服务（如自建 Embedding + 云数据库分片，或接外部向量库）；详见 02/07 |
| LLM 流式输出 | ⚠️ 受限 | 微信小程序 WebSocket/流式需通过云函数 SSE 代理或分片返回；详见 06 |
| OCR | ✅ 可行 | 微信 OCR 插件或腾讯云 OCR，云函数编排 |
| Word/PDF 导出 | ⚠️ 受限 | 小程序端生成能力弱，采用云函数 + 模板（docxtemplator/pdf-lib）生成后云存储回链 |
| 主动提醒 | ✅ 可行 | 订阅消息 + 云函数定时触发器；授权率低时降级页面内 |

### 3.2 合规可行性

- 法律咨询类应用不属于法律服务机构，**必须**全程附加免责声明并引导咨询专业律师（G5/G6）。
- 涉及用户案情、身份信息属敏感个人信息，需明示同意、最小化采集、加密存储（G1/G2）。
- 案例数据若来自中国裁判文书网等公开源，需标注来源、遵守使用规范。
- 风险：**不可出具"法律意见"**，仅提供"法律信息参考"。文案与 UI 措辞需统一合规口径。

### 3.3 成本可行性

- LLM 调用是主要变动成本。三层架构 + 缓存 + 简单问题不调 LLM，可将日均 3 次/用户的 LLM 调用压至 1–1.5 次（详见 02 容量成本模型）。
- 向量检索若自建，Embedding 调用成本可控（千问 Embedding 计价低）；若用外部向量库，需评估月费。
- 云函数调用次数与云数据库读写需在 02 监控，避免高频轮询。

### 3.4 人力与时间可行性

- 五阶段路线图（v1.0）整体合理。本集在 10 中将每阶段任务进一步拆解并标注依赖，便于排期。
- 关键路径：第一阶段（意图识别 + 规则引擎 + 对话页）→ 第三阶段（文书 + LLM）是体验核心，需保资源。
- P0 缺口需在对应阶段同步补齐，不能延后（如安全合规须在第一阶段就内建，而非事后补）。
