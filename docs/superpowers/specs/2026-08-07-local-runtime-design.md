# 子项目 A: 本地运行时 + 移动端调用 — 方案设计

- 日期: 2026-08-07
- 状态: 待评审
- 范围: 将 legal-agent 改造为**本地运行的工具软件**，支持多端安装包 + 移动端 Agent 调用

---

## 1. 背景与目标

用户希望 legal-agent 从「云端 SaaS」转变为「本地工具软件」：
- 用户下载安装即可用，无需服务器
- 移动端 App 能调用本机的法律 Agent 服务
- 数据完全本地化，不上传云端

## 2. 目标用户画像

| 角色 | 使用场景 | 需求 |
|-----|---------|------|
| 普通用户 | 手机/电脑上使用法律咨询 | 下载即用，数据本地 |
| 移动端 Agent | 调用本机法律 Agent API | HTTP API 可访问 |
| 开发者 | 二次开发/集成 | 清晰的插件架构 |

## 3. 架构决策

### 3.1 技术选型

| 平台 | 技术方案 | 理由 |
|-----|---------|------|
| Windows | Electron + NestJS + MongoDB | 成熟生态，开箱即用 |
| macOS | Electron + NestJS + MongoDB | 同上 |
| Linux | Electron + NestJS + MongoDB | 同上 |
| Android | Native App + SDK | 复用现有 SDK，HTTP 调用本机服务 |
| iOS | Native App + SDK | 复用现有 SDK，HTTP 调用本机服务 |

### 3.2 核心架构

```
┌─────────────────────────────────────────────────────────┐
│                    同一设备                              │
│                                                         │
│  ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │  Electron    │    │  Android     │    │  iOS      │ │
│  │  Desktop     │    │  Native App  │    │  Native   │ │
│  │  (Web UI)    │    │              │    │  App      │ │
│  └──────┬───────┘    └──────┬───────┘    └─────┬─────┘ │
│         │                   │                  │        │
│         └───────────────────┼──────────────────┘        │
│                             │ HTTP API                  │
│                    ┌────────▼────────┐                  │
│                    │  NestJS Server  │                  │
│                    │  (本地运行)      │                  │
│                    │  Port: 3000     │                  │
│                    └────────┬────────┘                  │
│                             │                           │
│                    ┌────────▼────────┐                  │
│                    │  MongoDB        │                  │
│                    │  (本地数据)     │                  │
│                    └─────────────────┘                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 3.3 关键设计决策

| 决策点 | 选择 | 理由 |
|-------|------|------|
| 数据库 | MongoDB（本地运行） | 保持与云端一致，无需迁移 |
| API 访问 | 本地 HTTP (127.0.0.1:3000) | 本机调用，无需公网 |
| 认证 | 无认证 | 本地信任，简化使用 |
| CORS | 开放本地网络 | 移动端可访问 |
| 安装包 | Electron Builder 打包 | 一键安装包，跨平台 |

## 4. 功能范围

### 4.1 必须实现

1. **本地运行时**
   - 启动时自动启动 NestJS 服务
   - 本地 MongoDB/SQLite 数据持久化
   - 开机自启动（可选）

2. **桌面 UI**
   - 复用现有 Web 前端（Electron 加载）
   - 系统集成（托盘图标、菜单栏）

3. **移动端调用**
   - 本地 HTTP API 可访问
   - CORS 开放给本地网络
   - 提供 API 文档（Swagger 本地可用）

4. **安装包**
   - Windows: `.exe` 安装程序
   - macOS: `.dmg` 安装包
   - Linux: `.AppImage` / `.deb`

### 4.2 可选增强

1. **数据导入/导出**
   - 导出本地数据库为 JSON/SQLite dump
   - 导入备份数据

2. **插件系统**
   - 允许第三方开发法律工具插件

3. **离线模式**
   - 无网络时仍可咨询（本地模型）

## 5. 非目标

- 云端部署（已有 Vercel 方案）
- 多用户实时同步
- 应用商店上架（桌面端）

## 6. 迁移策略

### 6.1 现有代码适配

1. **后端改造**
   - 添加 `NODE_ENV=local` 模式
   - 移除 Redis 依赖（或使用本地内存替代）
   - CORS 开放本地网络 (`http://localhost:*`, `http://127.0.0.1:*`)
   - 认证简化（本地模式跳过 JWT 验证）

2. **前端适配**
   - 复用现有 React 应用
   - API 地址默认 `http://localhost:3000`
   - 移除登录页（或简化为首次启动向导）

3. **SDK 适配**
   - 支持 `baseUrl: 'http://localhost:3000'`
   - 本地模式无需 Token

### 6.2 数据迁移

- 本地数据存储在 `~/.legal-agent/data/`
- 支持导入云端数据（JSON 格式）

## 7. 验收标准

1. 下载安装包后，双击运行即可使用
2. 无网络时仍可访问所有功能
3. 移动端 App 可通过 HTTP 调用本地 API
4. 数据存储在本地，不上传云端
