# 法律智能体 — AI Agent 设计方案

> 版本: 1.0 | 日期: 2026-07-19 | 状态: 已审批

## 一、项目背景

本项目旨在开发一个**法律领域的专用智能体**，参照蚂蚁集团"阿福"模式，专注于垂直法律领域的深度服务能力。智能体将覆盖法律咨询、文书生成、流程指导、案例检索四大核心功能，面向普通民众和法律从业者两类用户群体，支持民事、刑事、商事、行政等全法律领域。

## 二、核心目标

1. **意图识别** — 自动判断用户输入的法律领域和问题类型，路由到对应服务
2. **三层混合架构** — 规则引擎 → 法律知识库 → 大语言模型，分级处理不同复杂度问题
3. **记忆与个性化** — 记住用户信息、咨询历史、案件进展，提供个性化服务
4. **主动提醒** — 基于案件时间节点（如举证期限、开庭时间）主动推送提醒

## 三、整体架构

```
用户输入
  │
  ├─ 第一层：意图识别与分级
  │    └─ 关键词 + 正则匹配 → 判断问题类型和复杂度
  │
  ├─ 第二层：路由分发
  │    ├─ 简单问题 → 规则引擎（法条查询、常识问答）
  │    ├─ 中等问题 → 法律知识库（流程指导、材料清单）
  │    └─ 复杂问题 → 大语言模型（案例分析、文书生成）
  │
  └─ 第三层：记忆与个性化
       └─ 用户档案 + 对话历史 + 案件跟踪
```

## 四、现有项目参考

当前有一个已完成的食品领域智能体项目（`Taro版/`），具备完整的意图识别、记忆管理、主动提醒等模块。新项目的架构设计将借鉴其经验，但针对法律领域的特殊性进行深度定制。

### 可复用模式

| 模块 | 现有实现 | 法律领域适配 |
|------|---------|-------------|
| 意图识别 | `intentRouter.js`（关键词加权 + 正则模式） | 保留架构，替换为法律领域关键词库 |
| 记忆管理 | `memoryManager.js`（偏好 + 健康档案 + 对话历史） | 改为法律偏好 + 案件档案 + 对话历史 |
| 通知服务 | `notificationService.js`（订阅消息 + 定时任务） | 改为案件节点提醒（举证期限、开庭时间） |
| LLM 服务 | `ai/llm.js`（多厂商切换 + 知识库兜底） | 保留架构，注入法律知识作为上下文 |

### 需要重新设计的模块

| 模块 | 原因 |
|------|------|
| 规则引擎 | 法律规则与食品保鲜规则完全不同，需重新构建法律知识库 |
| 数据层 | 法律条文、案例、文书模板等数据结构完全不同 |
| 页面设计 | 法律文书生成、流程指导等页面需要全新设计 |

## 五、核心模块设计

### 5.1 意图识别层（Intent Router）

**职责：** 分析用户输入，判断法律领域和问题类型

**支持的意图类型：**

| 意图 | 关键词示例 | 路由目标 | 复杂度 |
|------|-----------|---------|--------|
| `legal_qa` | "民法典规定"、"什么是正当防卫"、"诉讼时效" | 规则引擎 / 知识库 | 低 |
| `document_generate` | "帮我写起诉状"、"合同模板"、"律师函" | LLM + 模板引擎 | 高 |
| `process_guide` | "我要起诉"、"立案流程"、"怎么举证" | 知识库（结构化流程） | 中 |
| `case_analysis` | "这个案子能赢吗"、"判多重"、"怎么辩护" | LLM + 案例库 | 高 |
| `material_checklist` | "离婚需要什么材料"、"立案要带什么" | 知识库（材料清单） | 中 |
| `general_qa` | 其他问题 | LLM 兜底 | - |

**实现方式：**
- 关键词匹配 + 上下文感知（多轮对话延续判断）
- 置信度评分：>=0.8 直接路由，0.5-0.8 LLM 辅助判断，<0.5 通用问答
- 支持对话历史注入（最近 12 轮）

### 5.2 规则引擎层（Rule Engine）

**职责：** 处理简单、结构化的法律问题

**知识库内容：**
- 常用法律条文索引（民法典、刑法、劳动法、行政诉讼法等）
- 法律术语解释
- 基础问答对（FAQ）

**特点：**
- 响应快、准确率高、无需 API 调用
- 支持法条全文检索和关键词匹配
- 每条回答标注法律依据（具体法条号）

### 5.3 法律知识库层（Legal Knowledge Base）

**职责：** 提供结构化的法律知识和服务

**知识内容：**
- 各类案件的办理流程和时间节点
- 不同场景所需材料清单
- 典型案例参考
- 法律文书模板库

**特点：**
- 结构化数据，支持组合查询
- 支持按案由、法院层级、地区筛选
- 模板支持变量替换（如当事人姓名、金额等）

### 5.4 大模型服务层（LLM Service）

**职责：** 处理复杂、开放性的法律问题

**使用场景：**
- 个性化文书生成（根据案情自动填充）
- 案件分析和策略建议
- 多轮深度法律咨询

**技术选型：**
- 优先使用通义千问 API（国内合规、中文能力强）
- 备选文心一言、讯飞星火等
- Prompt 工程：注入相关法律条文和案例作为上下文

**特点：**
- 灵活性强，能处理复杂和多轮对话
- 所有输出附带免责声明
- 支持流式输出提升用户体验

### 5.5 记忆与用户档案层（Memory & Profile）

**职责：** 管理用户信息和案件上下文

**记忆内容：**

| 类型 | 存储键 | 用途 |
|------|--------|------|
| 法律偏好 | `legal_preferences` | 关注的法律领域、常咨询的问题类型 |
| 案件档案 | `legal_case_profile` | 进行中的案件（案由、阶段、时间节点） |
| 对话历史 | `legal_dialog_history` | 最近 12 轮对话 |
| 使用习惯 | `legal_usage_pattern` | 常用功能、常查法条 |

**接口设计：**

```javascript
saveMemory(entry)           // 保存单条记忆
getRelevantMemories(intent) // 根据意图获取相关记忆
updateCase(caseData)        // 更新案件档案
getCaseTimeline()           // 获取案件时间线
cleanupOldest(n)            // 清理最旧的n条记录
```

## 六、页面设计

### 6.1 首页（pages/home）

**功能模块：**
- 快速入口卡片（法律咨询 / 文书生成 / 流程指导 / 案例检索）
- 常见问题推荐（根据用户画像动态调整）
- 案件进度卡片（如有进行中的案件）
- 浮动 AI 助手按钮（一键唤起对话）

### 6.2 AI 对话页（pages/ai-chat）

**功能：**
- 多轮法律咨询，支持文字输入
- 文件上传（证据材料、合同扫描件等）
- 意图识别结果可视化（显示当前意图类型图标）
- 快捷意图按钮（咨询/文书/流程/案例）
- 对话中自动附带上下文（如刚上传了合同，自动识别为文书审查）

### 6.3 文书生成页（pages/document-generator）

**功能：**
- 引导式表单，分步填写案件信息
- 支持文书类型选择（起诉状、答辩状、合同、律师函等）
- 实时预览生成的文书
- 支持导出为 Word/PDF

**交互流程：**
1. 选择文书类型
2. 填写当事人信息（姓名、身份证号、联系方式等）
3. 填写案件事实（时间、地点、经过、诉求等）
4. 选择适用法律条款（可选，默认自动匹配）
5. 预览并编辑生成的文书
6. 导出或分享

### 6.4 流程指导页（pages/process-guide）

**功能：**
- 可视化案件流程图（时间轴形式）
- 每个节点的详细说明和操作指南
- 材料清单（可勾选已完成项）
- 时间节点提醒（举证期限、开庭时间等）

### 6.5 案例检索页（pages/case-search）

**功能：**
- 按案由搜索类似案例
- 筛选条件（法院层级、判决年份、胜诉/败诉）
- 案例详情展示（案情摘要、判决结果、法律依据）
- 统计图表（同类案件判决趋势）

### 6.6 我的页面（pages/mine）

**功能模块：**
- 咨询历史记录
- 进行中的案件列表
- 已生成的文书档案
- 法律偏好设置
- 订阅消息管理入口

## 九、实施路线图

**交付物：**
- `services/legal/intentRouter.js`（法律意图识别）
- `data/legalIntents.js`（法律意图定义库）
- `services/legal/ruleEngine.js`（法律规则引擎）
- `data/lawArticles.js`（常用法律条文库）

**验收标准：**

- 对话支持多轮上下文
- 意图识别准确率 >= 80%
- 常见法条查询响应时间 < 100ms

### 第二阶段：法律知识库 + 流程指导

**交付物：**
- `services/legal/knowledgeBase.js`（法律知识库服务）

- `pages/process-guide` 页面（流程指导）

**验收标准：**
- 覆盖民事、刑事、商事、行政四大类常见案件流程
- 材料清单完整率 >= 90%
- 案例检索支持按案由、年份筛选

### 第三阶段：文书生成 + LLM 集成

**交付物：**
- `services/legal/documentGenerator.js`（文书生成服务）
- `services/legal/llm.js`（LLM 服务封装）
- `pages/document-generator` 页面（文书生成）

**验收标准：**
- 支持至少 4 种常见文书类型的自动生成
- 文书格式规范，字段填充准确
- LLM 回答附带法律依据引用
- 所有 AI 输出附带免责声明

### 第四阶段：记忆系统 + 主动提醒

**交付物：**
- `services/legal/memoryManager.js`（法律记忆管理）

**验收标准：**
- 能记住用户偏好并应用于推荐
- 案件节点提前 3 天预警

**交付物：**
- 使用统计面板

**验收标准：**
- 首屏加载时间 < 2 秒
- 对话平均响应时间 < 3 秒
- 用户满意度 >= 4/5

## 十、关键设计原则

### 1. 准确性优先

涉及法律条文的问题，优先使用规则引擎，确保引用准确。LLM 生成的内容必须经过法律知识库校验。

### 2. 渐进式引导

复杂任务（如文书生成、案例分析）采用多步表单引导用户填写，避免一次性要求过多信息。

### 3. 免责声明

所有 AI 回答附带"仅供参考，不构成法律意见，具体问题请咨询专业律师"的提示。

### 4. 可追溯性

每条回答标注法律依据（具体法条号），方便用户核实。

### 5. 成本优化

简单问题不调用 LLM，降低 API 成本。LLM 调用采用缓存策略，相同问题不重复请求。

## 十一、不做的事情（YAGNI 裁剪）

- 在线律师对接（留接口但不实现）
- 视频法律咨询（先用文字对话）
- 多语言支持（先聚焦中文）
- 跨平台部署（先做微信小程序）
- 付费功能（一期免费）

## 十二、风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 法律条文更新 | 知识库过期 | 建立定期更新机制，接入司法部官网 API |
| 意图识别准确率不足 | 用户体验差 | 持续优化关键词，收集失败案例 |
| LLM API 不可用 | 对话降级 | 知识库兜底 + 规则引擎 |
| 法律风险 | 错误建议导致用户损失 | 强制免责声明 + 复杂问题引导咨询专业律师 |
| 隐私泄露 | 用户案件信息泄露 | 数据加密存储 + 权限控制 |
| 订阅消息授权率低 | 提醒功能失效 | 仅在页面内展示降级提醒 |

## 十三、成功指标

1. 用户日均对话次数 >= 3 次
2. 意图识别准确率 >= 80%
3. 文书生成满意度 >= 4/5
4. 用户留存率（7 日）>= 30%
5. 法律咨询问题解决率 >= 70%
